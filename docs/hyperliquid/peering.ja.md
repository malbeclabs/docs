## ノードの接続

承認後、**ピア IP** をお送りします。非バリデーティングノードをそのピア IP に向け、ファイアウォールを開放し、ノードを再起動してください。

### 1. ゴシップ設定の構成

`~/override_gossip_config.json` を以下の内容に置き換え、ピア IP を使用してください：

```json
{
  "root_node_ips": [{"Ip": "<PEER_IP>"}],
  "try_new_peers": false,
  "split_client_blocks": true,
  "chain": "Mainnet"
}
```

| 設定 | 理由 |
|--|--|
| `root_node_ips` | DoubleZero ピアが唯一のアップストリームです。 |
| `try_new_peers: false` | ノードを DoubleZero ピアに固定します。パブリックピアには切り替わりません。 |
| `split_client_blocks: true` | mempool トランザクションを `~/hl/data/mempool_txs/` にストリーミングします。 |

!!! note "ディスクと帯域幅の計画"
    `split_client_blocks: true` を設定すると、ノードは完全な mempool をディスクに書き込みます。
    mempool からの書き込みだけで1日あたり数百 GB から約 1 TB、さらにその他のノード出力からも
    同程度の書き込みが発生します。ゴシップはワイヤ上で圧縮されるため、
    インバウンド帯域幅はそれより低くなります。テストノードでは約 110 GB/日でした。
    `~/hl/data/` に保持ポリシーを設定してください（例: 数時間以上古いファイルを削除）。
    設定しないと1日以内にディスクがいっぱいになります。

### 2. ピアに対するファイアウォールの開放

**`<PEER_IP>` からのインバウンド TCP および UDP 4001〜4002** を許可してください。クラウドセキュリティグループとホストファイアウォールの両方で設定します。

ノードが接続すると、ピアはノードの 4001 および 4002 に接続し返して到達可能かチェックします。このチェックがブロックされると、接続は確立されますがデータは届きません。また、ピアへの 4001〜4002 のアウトバウンド接続も許可してください。

### 3. ノードの再起動

```bash
sudo systemctl restart hl-node   # or however you run hl-visor
```

ノードは起動時にこのファイルを読み込みます。実行中に加えた変更は完全に反映されない場合があるため、変更後は毎回再起動してください。キャッチアップには通常 5〜15 分かかります。

### 4. 動作確認

```bash
ss -tn state established '( dport = :4001 )'     # one connection, to <PEER_IP>
journalctl -u hl-node -f | grep 'applied block'  # blocks are being applied
ls -l ~/hl/data/mempool_txs/                     # mempool files are growing
```

!!! warning "接続はされているがデータがない"
    ピアがノードの 4001〜4002 に到達できていません。手順 2 のインバウンドルールを確認してください。

!!! note "パブリックピアへのフォールバックなし"
    `try_new_peers: false` の場合、ノードは DoubleZero ピアに到達できない場合、接続を待ち続けます。パブリックピアには切り替わりません。`Peer full` や接続タイムアウトが繰り返し発生する場合は、お問い合わせください。

## アップタイム

目標: 月間 99.9% の可用性。

- 冗長フィード。各プロキシは当社の2つの非バリデーティングノードの両方とピアリングしています。これらのノードは独立したソース（Foundation とセントリー）からブロックを取得します。一方のセッションまたはソースがダウンしても、障害パスが復旧する間、もう一方がブロックの配信を継続します。
- 当社のノードはプロキシティアの背後に位置します。外部ピアは Block Proxy にのみ到達します。プロキシが障害を起こした場合、そのピアは別の正常なプロキシに再接続します。負荷が当社のノードにフォールバックすることはありません。
- プロキシは使い捨てのキャッシュ（スナップショット、ローリングブロックウィンドウ、ライブバッファ）のみを保持し、権威あるチェーン状態は保持しません。異常なプロキシは自動的に置き換えられます。代替プロキシはアップストリームセッションとキャッシュのレディネスチェックに合格した後にのみサービスに投入されます。その際、当社の非バリデーティングノードは再起動されません。

- プロキシを追加することでスケールします。各プロキシは多数のピアにサービスを提供しますが、当社の各非バリデーティングノードからは単一のピアとしてカウントされます。
