# ピアリングアクセス

ピアリングは、非バリデーティングノードに対して、Block Proxy を介した低遅延かつ重複排除済みの Hyperliquid ゴシップフィード（mempool を含む）を提供します。Edge マーケットデータフィードは含まれません。それらについては [Subscribe to Hyperliquid (Edge)](edge.md) をご覧ください。概要：[Hyperliquid](index.md)。

## ピアリングのリクエスト

ピアリングに関する詳細情報は [Telegram](https://t.me/doublezero_telegram_bot?start=fromwebsite) からご確認いただけます。ノードの静的パブリック IP（およびリージョン）をお知らせください。ノードの詳細情報と決済が完了してから、**1〜3 営業日**以内にピアの詳細をお届けします。

## 有料ピアリングの理由

パブリックな Hyperliquid ルートピアは共有されています。スロットは競合し、ピアはローテーションやレート制限を行い、多くのピアは mempool を転送しません。予約済みのピアリングスロットを利用することで、パブリック容量を奪い合う代わりに、DoubleZero 上の安定したアップストリームを得ることができます。

## 仕組み

- 2 つのゴシップソース：Hyper Foundation の非バリデーティングノードからの A フィードと、セントリーからの B フィード。
- お客様は、水平スケーリングする Block Proxy 層とピアリングします。各プロキシは当社の両方の非バリデーティングノードとピアリングし、それぞれに対して通常のゴシップピア 1 台のように見えます。
- プロキシは A と B を調停し、ピア向けに重複排除済みの単一ゴシップフィードにまとめるため、どちらのソースが切断されてもストリームは停止しません。
- プロキシを追加することで容量を拡大できます。当社の非バリデーティングノードへの負荷はピア数に伴って増加しません。

## アップタイム

目標：月間 99.9% の可用性。

- 冗長フィード。各プロキシは当社の両方の非バリデーティングノードとピアリングします。これらのノードは独立したソース（Foundation とセントリー）からブロックを受信します。一方のセッションまたはソースが切断されても、障害パスが復旧する間、もう一方がブロックの配信を継続します。
- 当社のノードはプロキシ層の背後に配置されます。外部ピアは Block Proxy にのみ到達します。プロキシが障害を起こした場合、そのピアは別の正常なプロキシに再接続します。負荷が当社のノードにフォールバックすることはありません。
- プロキシは使い捨てのキャッシュのみ（スナップショット、ローリングブロックウィンドウ、ライブバッファ）を保持し、権威あるチェーンステートは保持しません。障害プロキシは自動的に置き換えられます。交換用プロキシは、アップストリームセッションとキャッシュがレディネスチェックに合格した後にのみサービスに投入されます。そのために当社の非バリデーティングノードが再起動されることはありません。

## オートスケーリング

- プロキシを追加することでスケールします。各プロキシは多数のピアにサービスを提供しますが、当社の各非バリデーティングノードにおいては単一ピアとしてカウントされます。
- ノード負荷はピア数ではなくプロキシ数に比例します。
- 新しいプロキシはキャッシュのウォームアップとレディネスチェックの合格後に起動します。フルチェーン再同期は不要です。
- 参加するピアは、ブートストラップスナップショットをスナップショットサービスから、キャッチアップブロックをプロキシ自身のストアから取得し、当社の非バリデーティングノードからは取得しません。新規ピアの急増はプロキシ層に対してのみ影響します。
