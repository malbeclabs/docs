# 피어링 액세스

피어링은 비검증 노드에 멤풀을 포함한 Block Proxy를 통해 저지연, 중복 제거된 Hyperliquid 가십 피드를 제공합니다. Edge 시장 데이터 피드는 포함되지 않습니다. Edge 시장 데이터 피드에 대해서는 [Hyperliquid (Edge) 구독](edge.md)을 참조하세요. 개요: [Hyperliquid](index.md).

| | |
|--|--|
| 대상 | 운영 중인 비검증 노드 |
| 제공 내용 | Block Proxy를 통한 하나의 중재된 가십 피드 (블록 + 멤풀) |
| 수신 호스트 | 1개 IP 포함 |
| 가격 | $999/월 (Edge 시장 데이터 미포함) |
| 가용성 목표 | 월간 99.9% |

## 피어링 요청

피어링에 대한 자세한 정보는 [Telegram](https://t.me/doublezero_telegram_bot?start=fromwebsite)을 통해 확인할 수 있습니다. 노드의 고정 공인 IP(및 리전)를 포함하세요. 노드 세부 정보 및 결제 완료 후 **영업일 기준 1~3일** 이내에 피어 세부 정보를 받으실 수 있습니다.

## 노드 연결

승인되면, **피어 IP**를 전달해 드립니다. 비검증 노드를 해당 IP로 지정하고, 방화벽을 열고, 노드를 재시작하세요.

### 1. 가십 설정 구성

`~/override_gossip_config.json`을 피어 IP를 사용하여 다음과 같이 교체하세요:

```json
{
  "root_node_ips": [{"Ip": "<PEER_IP>"}],
  "try_new_peers": false,
  "split_client_blocks": true,
  "chain": "Mainnet"
}
```

| 설정 | 이유 |
|--|--|
| `root_node_ips` | DoubleZero 피어가 유일한 업스트림입니다. |
| `try_new_peers: false` | 노드를 DoubleZero 피어에 고정합니다. 퍼블릭 피어로 전환되지 않습니다. |
| `split_client_blocks: true` | 멤풀 트랜잭션을 `~/hl/data/mempool_txs/`로 스트리밍합니다. |

### 2. 피어에 대해 방화벽 열기

**`<PEER_IP>`로부터의 인바운드 TCP 및 UDP 4001–4002**를 허용하세요. 클라우드 보안 그룹과 호스트 방화벽 모두에서 설정하세요.

노드가 연결되면, 피어가 4001 및 4002 포트로 노드에 역방향 연결하여 도달 가능 여부를 확인합니다. 이 확인이 차단되면, 연결은 열리지만 데이터가 도착하지 않습니다. 또한 피어로의 4001–4002 아웃바운드 연결도 허용하세요.

### 3. 노드 재시작

```bash
sudo systemctl restart hl-node   # or however you run hl-visor
```

노드는 시작 시 이 파일을 읽습니다. 실행 중에 변경한 사항은 완전히 적용되지 않을 수 있으므로, 변경할 때마다 재시작하세요. 동기화에는 보통 5~15분이 소요됩니다.

### 4. 정상 작동 확인

```bash
ss -tn state established '( dport = :4001 )'     # one connection, to <PEER_IP>
journalctl -u hl-node -f | grep 'applied block'  # blocks are being applied
ls -l ~/hl/data/mempool_txs/                     # mempool files are growing
```

!!! warning "연결되었지만 데이터 없음"
    피어가 4001–4002 포트로 노드에 도달할 수 없습니다. 2단계의 인바운드 규칙을 확인하세요.

!!! note "퍼블릭 피어로 폴백 없음"
    `try_new_peers: false` 설정 시, 노드는 DoubleZero 피어에 도달할 수 없으면 대기합니다. 퍼블릭 피어로 전환되지 않습니다. `Peer full` 또는 연결 시간 초과가 반복되면 문의해 주세요.

## 유료 피어링인 이유

퍼블릭 Hyperliquid 루트 피어는 공유됩니다: 슬롯이 경합되고, 피어가 교체되거나 속도가 제한되며, 많은 피어가 멤풀을 전달하지 않습니다. 예약된 피어링 슬롯은 퍼블릭 용량을 두고 경쟁하는 대신 DoubleZero에서 안정적인 업스트림을 제공합니다.

## 작동 방식

- 두 가지 가십 소스: Hyper Foundation의 비검증 노드에서 오는 A 피드와 센트리에서 오는 B 피드.
- 고객은 수평 확장되는 Block Proxy 티어와 피어링합니다. 각 프록시는 두 비검증 노드 모두와 피어링하며, 각 노드에게 일반적인 하나의 가십 피어로 보입니다.
- 프록시는 A와 B를 하나의 중복 제거된 가십 피드로 중재하여 피어에 전달하므로, 어느 소스가 중단되어도 스트림이 멈추지 않습니다.
- 프록시를 추가하여 용량을 확장합니다. 비검증 노드의 부하는 피어 수에 따라 증가하지 않습니다.

## 가동 시간

목표: 월간 99.9% 가용성.

- 이중화된 피드. 각 프록시는 두 비검증 노드 모두와 피어링합니다. 이 노드들은 독립적인 소스(Foundation 및 센트리)에서 블록을 받습니다. 하나의 세션이나 소스가 중단되면, 실패한 경로가 복구되는 동안 나머지가 블록 흐름을 유지합니다.
- 우리 노드들은 프록시 티어 뒤에 있습니다. 외부 피어는 Block Proxy에만 도달합니다. 프록시가 실패하면, 해당 피어들은 다른 정상 프록시에 재연결됩니다. 부하가 우리 노드로 돌아가지 않습니다.
- 프록시는 권한 있는 체인 상태가 아닌 일회용 캐시(스냅샷, 롤링 블록 윈도우, 라이브 버퍼)만 보유합니다. 문제가 있는 프록시는 자동으로 교체됩니다. 교체 프록시는 업스트림 세션과 캐시가 준비 상태 확인을 통과한 후에만 서비스에 투입됩니다. 이를 위해 비검증 노드를 재시작하지 않습니다.

## 자동 확장

- 프록시를 추가하여 확장합니다. 각 프록시는 많은 피어를 서비스하지만 각 비검증 노드에서는 단일 피어로 카운트됩니다.
- 노드 부하는 피어 수가 아닌 프록시 수에 비례합니다.
- 새 프록시는 캐시가 워밍업되고 준비 상태 확인이 통과되면 가동됩니다. 전체 체인 재동기화가 필요하지 않습니다.
- 합류하는 피어는 스냅샷 서비스에서 부트스트랩 스냅샷을, 프록시 자체 스토어에서 캐치업 블록을 가져오며, 비검증 노드에서 직접 가져오지 않습니다. 새 피어의 급증은 프록시 티어에서 처리됩니다.

## 가격

피어링 $999/월. 멤풀 포함. Edge 시장 데이터 피드 미포함. 수신 호스트(IP) 1개 포함. 피어링은 Edge 시장 데이터와 번들 또는 할인 제공되지 않습니다.
