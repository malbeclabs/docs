# 피어링 액세스

피어링은 비검증 노드에 멤풀을 포함한 Block Proxy를 통해 저지연, 중복 제거된 Hyperliquid 가십 피드를 제공합니다. Edge 시장 데이터 피드는 포함되지 않습니다. Edge 시장 데이터 피드에 대해서는 [Hyperliquid (Edge) 구독](edge.md)을 참조하세요. 개요: [Hyperliquid](index.md).

| | |
|--|--|
| 대상 | 직접 운영하는 비검증 노드 |
| 제공 내용 | Block Proxy를 통한 하나의 중재된 가십 피드 (블록 + 멤풀) |
| 수신 호스트 | 1개 IP 포함 |
| 가격 | $999/월 (Edge 시장 데이터 미포함) |
| 가용성 목표 | 월간 99.9% |

## 피어링 요청

피어링에 대한 자세한 정보는 [Telegram](https://t.me/doublezero_telegram_bot?start=fromwebsite)을 통해 확인할 수 있습니다. 노드의 고정 공용 IP(및 리전)를 포함하세요. 노드 세부 정보 확인 및 결제 완료 후 **영업일 기준 1~3일** 이내에 피어 세부 정보를 받을 수 있습니다.

## 노드 연결

승인이 완료되면 **피어 IP**를 보내드립니다. 비검증 노드가 해당 IP를 가리키도록 설정하고, 방화벽을 열고, 노드를 재시작하세요.

### 1. 가십 설정 구성

`~/override_gossip_config.json` 파일을 피어 IP를 사용하여 다음과 같이 교체하세요:

```json
{
  "root_node_ips": [{"Ip": "<PEER_IP>"}],
  "try_new_peers": false,
  "split_client_blocks": true,
  "chain": "Mainnet"
}
```

| 설정 | 이유 |
|--|--|
| `root_node_ips` | DoubleZero 피어가 유일한 업스트림입니다. |
| `try_new_peers: false` | 노드를 DoubleZero 피어에 유지합니다. 공용 피어로 전환하지 않습니다. |
| `split_client_blocks: true` | 멤풀 트랜잭션을 `~/hl/data/mempool_txs/`로 스트리밍합니다. |

!!! note "디스크 및 대역폭 계획"
    `split_client_blocks: true`를 설정하면 노드가 전체 멤풀을 디스크에 기록합니다.
    멤풀에서 하루에 수백 GB에서 약 1 TB의 쓰기가 발생하며,
    기타 노드 출력에서도 비슷한 양이 발생합니다. 인바운드
    대역폭은 가십이 전송 시 압축되므로 더 낮습니다; 테스트
    노드에서는 하루 약 110 GB를 수신했습니다. `~/hl/data/`에 대한 보존 정책을
    설정하세요(예: 몇 시간이 지난 파일 삭제). 그렇지 않으면
    디스크가 하루 이내에 가득 찹니다.

### 2. 피어에 대한 방화벽 열기

**`<PEER_IP>`로부터의 인바운드 TCP 및 UDP 4001–4002**를 허용하세요. 클라우드 보안 그룹과 호스트 방화벽 모두에서 설정하세요.

노드가 연결되면 피어가 4001 및 4002 포트를 통해 노드에 역으로 연결하여 도달 가능 여부를 확인합니다. 이 확인이 차단되면 연결은 열리지만 데이터가 도착하지 않습니다. 또한 피어로의 4001–4002 아웃바운드 연결도 허용하세요.

### 3. 노드 재시작

```bash
sudo systemctl restart hl-node   # or however you run hl-visor
```

노드는 시작 시 이 파일을 읽습니다. 실행 중 변경 사항은 완전히 적용되지 않을 수 있으므로 변경할 때마다 재시작하세요. 동기화에는 보통 5~15분이 소요됩니다.

### 4. 정상 동작 확인

```bash
ss -tn state established '( dport = :4001 )'     # one connection, to <PEER_IP>
journalctl -u hl-node -f | grep 'applied block'  # blocks are being applied
ls -l ~/hl/data/mempool_txs/                     # mempool files are growing
```

!!! warning "연결되었지만 데이터 없음"
    피어가 4001–4002 포트를 통해 노드에 도달할 수 없습니다. 2단계의 인바운드 규칙을 확인하세요.

!!! note "공용 피어로의 폴백 없음"
    `try_new_peers: false` 설정 시, 노드는 DoubleZero 피어에 도달할 수 없으면 대기합니다. 공용 피어로 전환하지 않습니다. 반복적인 `Peer full` 또는 연결 시간 초과가 발생하면 저희에게 연락하세요.

## 유료 피어링의 이유

공용 Hyperliquid 루트 피어는 공유됩니다: 슬롯은 경합하고, 피어는 순환하거나 속도를 제한하며, 많은 피어가 멤풀을 전달하지 않습니다. 예약된 피어링 슬롯은 공용 용량을 두고 경쟁하는 대신 DoubleZero에서 안정적인 업스트림을 제공합니다.

## 작동 방식

- 두 가지 가십 소스: Hyper Foundation의 비검증 노드에서 오는 A 피드와 센트리에서 오는 B 피드.
- 고객은 수평적으로 확장되는 Block Proxy 티어와 피어링합니다. 각 프록시는 두 비검증 노드 모두와 피어링하며, 각 노드에 대해 하나의 일반 가십 피어처럼 보입니다.
- 프록시는 A와 B를 하나의 중복 제거된 가십 피드로 중재하여 피어에 제공하므로, 어느 소스가 끊기더라도 스트림이 중단되지 않습니다.
- 프록시를 추가하여 용량을 확장합니다. 비검증 노드의 부하는 피어 수에 따라 증가하지 않습니다.

## 가용성

목표: 월간 99.9% 가용성.

- 이중화 피드. 각 프록시는 두 비검증 노드 모두와 피어링합니다. 해당 노드들은 독립적인 소스(Foundation 및 센트리)에서 블록을 수신합니다. 하나의 세션 또는 소스가 끊기면, 실패한 경로가 복구되는 동안 다른 경로가 블록 흐름을 유지합니다.
- 노드는 프록시 티어 뒤에 위치합니다. 외부 피어는 Block Proxy에만 접근합니다. 프록시가 실패하면 해당 피어들은 다른 정상 프록시에 재연결합니다. 부하가 노드로 직접 전달되는 일은 없습니다.
- 프록시는 권한 있는 체인 상태가 아닌 일회성 캐시(스냅샷, 롤링 블록 윈도우, 라이브 버퍼)만 보유합니다. 문제가 있는 프록시는 자동으로 교체됩니다. 교체 프록시는 업스트림 세션과 캐시가 준비 상태 점검을 통과한 후에만 서비스에 투입됩니다. 이를 위해 비검증 노드가 재시작되지는 않습니다.

## 자동 확장

- 프록시를 추가하여 확장합니다. 각 프록시는 많은 피어를 서비스하지만 각 비검증 노드에서는 단일 피어로 카운트됩니다.
- 노드 부하는 피어 수가 아닌 프록시 수에 따라 변합니다.
- 새 프록시는 캐시가 워밍업되고 준비 상태 점검을 통과하면 가동됩니다. 전체 체인 재동기화는 필요하지 않습니다.
- 새로 참여하는 피어는 비검증 노드가 아닌 스냅샷 서비스에서 부트스트랩 스냅샷을 가져오고, 프록시 자체 저장소에서 캐치업 블록을 수신합니다. 새 피어의 급증은 노드가 아닌 프록시 티어가 처리합니다.

## 가격

피어링 $999/월. 멤풀 포함. Edge 시장 데이터 피드 미포함. 수신 호스트(IP) 1개 포함. 피어링은 Edge 시장 데이터와 번들 또는 할인 적용되지 않습니다.
