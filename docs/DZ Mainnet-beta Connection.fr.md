Choisissez le réseau DoubleZero qui correspond à votre cluster Solana : `mainnet-beta` ou `testnet`. Installez les paquets correspondants dans la section [configuration](setup.md), et utilisez ce même réseau pour chaque commande ci-dessous.

!!! Note inline end
    Le mode IBRL ne nécessite pas de redémarrage des clients validateurs, car il utilise votre adresse IP publique existante.

Les validateurs Solana se connectent à DoubleZero en mode IBRL en suivant les étapes de cette page.

Chaque validateur Solana possède sa propre **paire de clés d'identité** ; à partir de celle-ci, on extrait la clé publique connue sous le nom d'**identifiant de nœud** (node ID). C'est l'empreinte unique du validateur sur le réseau Solana.

Une fois le DoubleZeroID et l'identifiant de nœud identifiés, vous prouverez la propriété de votre machine. Cela se fait en créant un message qui inclut le DoubleZeroID signé avec la clé d'identité du validateur. La signature cryptographique résultante sert de preuve vérifiable que vous contrôlez le validateur.

Enfin, vous soumettrez une **demande de connexion à DoubleZero**. Cette demande communique : *« Voici mon identité, voici la preuve de propriété, et voici comment j'ai l'intention de me connecter. »* DoubleZero valide ces informations, accepte la preuve et provisionne l'accès réseau pour le validateur sur DoubleZero.

Ce guide permet à 1 Validateur Principal de s'enregistrer, ainsi que jusqu'à 3 machines de secours/basculement en même temps.

## Prérequis

- Solana CLI installé et dans le $PATH
- Pour les validateurs : Permission d'accéder au fichier de paire de clés d'identité du validateur (ex. : validator-keypair.json) sous l'utilisateur sol
- Pour les validateurs : Vérifiez que la clé d'identité du validateur Solana connecté dispose d'au moins 1 SOL
- Les règles de pare-feu autorisent les connexions sortantes pour DoubleZero et Solana RPC selon les besoins, y compris
 GRE (ip proto 47) et BGP (169.254.0.0/16 sur tcp/179)

!!! info
    L'identifiant du Validateur sera vérifié dans le gossip Solana pour déterminer l'IP cible. L'IP cible et l'identifiant DoubleZero seront ensuite utilisés lors de l'ouverture d'un tunnel GRE entre votre machine et le dispositif DoubleZero cible.

    À noter : Dans le cas où vous avez un identifiant factice et un identifiant principal sur la même IP, seul l'identifiant principal sera utilisé pour l'enregistrement de la machine. En effet, l'identifiant factice n'apparaîtra pas dans le gossip et ne pourra donc pas être utilisé pour vérifier l'IP de la machine cible.

## 2. Ouvrir le port 44880

Les utilisateurs doivent ouvrir le port 44880 pour utiliser certaines [fonctionnalités de routage](https://github.com/malbeclabs/doublezero/blob/main/rfcs/rfc7-client-route-liveness.md).

Pour ouvrir le port 44880, vous pouvez mettre à jour les tables IP comme suit :

```
sudo iptables -A INPUT -i doublezero0 -p udp --dport 44880 -j ACCEPT
sudo iptables -A OUTPUT -o doublezero0 -p udp --dport 44880 -j ACCEPT
```


notez les options `-i doublezero0`, `-o doublezero0` qui restreignent cette règle uniquement à l'interface DoubleZero

Ou avec UFW :

```
sudo ufw allow in on doublezero0 to any port 44880 proto udp
sudo ufw allow out on doublezero0 to any port 44880 proto udp
```


notez les options `in on doublezero0`, `out on doublezero0` qui restreignent cette règle uniquement à l'interface DoubleZero

## 3. Attester la Propriété du Validateur

!!! note "Option réseau"
    Les commandes Passport ci-dessous utilisent `-u mainnet-beta`. Sur testnet, utilisez `-u testnet` (ou `-ut`) à la place.

Avec votre Environnement DoubleZero configuré, il est maintenant temps d'attester votre Propriété du Validateur.

L'identifiant DoubleZero que vous avez créé lors de la [configuration](setup.md) de votre validateur principal doit être utilisé sur toutes les machines de secours.

L'identifiant de votre machine principale peut être trouvé avec `doublezero address`. Le même identifiant doit se trouver dans `~/.config/doublezero/id.json` sur toutes les machines du cluster.

Pour ce faire, vous allez d'abord vérifier que la machine depuis laquelle vous exécutez les commandes est votre **Validateur Principal** avec :

```
doublezero-solana passport find-validator -u mainnet-beta
```

Ceci vérifie que le validateur est enregistré dans le gossip et apparaît dans le calendrier des leaders.

Sortie attendue :

```

Detected public IP: 11.11.11.111
Validator ID: ValidatorIdentity111111111111111111111111111
Gossip IP: 11.11.11.111
In Leader scheduler
✅ This validator can connect as a primary in DoubleZero 🖥️  💎. It is a leader scheduled validator.
```

!!! info
    Le même flux de travail est utilisé pour une ou plusieurs machines.
    Pour enregistrer une seule machine, excluez les arguments "--backup-validator-ids" ou "backup_ids=" de toutes les commandes de cette page.

Maintenant, sur toutes les machines de secours sur lesquelles vous avez l'intention d'exécuter votre **Validateur Principal**, exécutez la commande suivante :
```
doublezero-solana passport find-validator -u mainnet-beta
```

```

Cette sortie est attendue. Le nœud de secours ne peut pas être dans le calendrier des leaders au moment de la création du pass.

Vous allez maintenant exécuter cette commande sur **toutes les machines de secours** sur lesquelles vous prévoyez d'utiliser le compte de vote et l'identité de votre **Validateur Principal**.
