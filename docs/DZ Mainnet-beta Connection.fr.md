Choisissez le réseau DoubleZero correspondant à votre cluster Solana : `mainnet-beta` ou `testnet`. Installez les paquets correspondants dans la [configuration](setup.md), et utilisez ce même réseau pour chaque commande ci-dessous.

!!! Note inline end
    Le mode IBRL ne nécessite pas de redémarrer les clients validateurs, car il utilise votre adresse IP publique existante.

Les validateurs Solana se connectent à DoubleZero en mode IBRL en suivant les étapes de cette page.

Chaque validateur Solana possède sa propre **paire de clés d'identité** ; à partir de celle-ci, extrayez la clé publique connue sous le nom de **node ID**. C'est l'empreinte unique du validateur sur le réseau Solana.

Une fois le DoubleZeroID et le node ID identifiés, vous prouverez la propriété de votre machine. Cela se fait en créant un message qui inclut le DoubleZeroID signé avec la clé d'identité du validateur. La signature cryptographique résultante sert de preuve vérifiable que vous contrôlez le validateur.

Enfin, vous soumettrez une **demande de connexion à DoubleZero**. Cette demande communique : *« Voici mon identité, voici la preuve de propriété, et voici comment j'ai l'intention de me connecter. »* DoubleZero valide ces informations, accepte la preuve et provisionne l'accès réseau pour le validateur sur DoubleZero.

Ce guide permet à 1 validateur principal de s'enregistrer, et jusqu'à 3 machines de secours/basculement en même temps.

## Prérequis {#prerequisites}

- Solana CLI installé et dans le $PATH
- Pour les validateurs : permission d'accéder au fichier de paire de clés d'identité du validateur (par ex., validator-keypair.json) sous l'utilisateur sol
- Pour les validateurs : vérifiez que la clé d'identité du validateur Solana connecté dispose d'au moins 1 SOL
- Les règles de pare-feu autorisent les connexions sortantes pour DoubleZero et Solana RPC selon les besoins, y compris
 GRE (ip proto 47) et BGP (169.254.0.0/16 sur tcp/179)

!!! info
    L'ID du validateur sera vérifié par rapport au gossip Solana pour déterminer l'IP cible. L'IP cible et l'ID DoubleZero seront ensuite utilisés lors de l'ouverture d'un tunnel GRE entre votre machine et le dispositif DoubleZero cible.

    À noter : dans le cas où vous avez un ID factice et un ID principal sur la même IP, seul l'ID principal sera utilisé pour l'enregistrement de la machine. En effet, l'ID factice n'apparaîtra pas dans le gossip et ne peut donc pas être utilisé pour vérifier l'IP de la machine cible.

## 2. Ouvrir le port 44880 {#2-open-port-44880}

Les utilisateurs doivent ouvrir le port 44880 pour utiliser certaines [fonctionnalités de routage](https://github.com/malbeclabs/doublezero/blob/main/rfcs/rfc7-client-route-liveness.md).

Pour ouvrir le port 44880, vous pouvez mettre à jour les tables IP comme suit :

```
sudo iptables -A INPUT -i doublezero0 -p udp --dport 44880 -j ACCEPT
sudo iptables -A OUTPUT -o doublezero0 -p udp --dport 44880 -j ACCEPT
```


notez les options `-i doublezero0`, `-o doublezero0` qui restreignent cette règle à l'interface DoubleZero uniquement

Ou UFW comme suit :

```
sudo ufw allow in on doublezero0 to any port 44880 proto udp
sudo ufw allow out on doublezero0 to any port 44880 proto udp
```


notez les options `in on doublezero0`, `out on doublezero0` qui restreignent cette règle à l'interface DoubleZero uniquement

## 3. Attester la propriété du validateur {#3-attest-validator-ownership}

!!! note "Option réseau"
    Les commandes Passport ci-dessous utilisent `-u mainnet-beta`. Sur testnet, utilisez `-u testnet` (ou `-ut`) à la place.

Avec votre environnement DoubleZero configuré, il est maintenant temps d'attester la propriété de votre validateur.

L'ID DoubleZero que vous avez créé lors de la [configuration](setup.md) de votre validateur principal doit être utilisé sur toutes les machines de secours.

L'ID sur votre machine principale peut être trouvé avec `doublezero address`. Le même ID doit être présent dans `~/.config/doublezero/id.json` sur toutes les machines du cluster.

Pour ce faire, vous vérifierez d'abord que la machine depuis laquelle vous exécutez les commandes est bien votre **validateur principal** avec :

```
doublezero-solana passport find-validator -u mainnet-beta
```

Cela vérifie que le validateur est enregistré dans le gossip et apparaît dans le calendrier des leaders.

Sortie attendue :

```

Gossip IP: 11.11.11.111
In Leader scheduler
✅ This validator can connect as a primary in DoubleZero 🖥️  💎. It is a leader scheduled validator.
```

    Le même flux de travail est utilisé pour une ou plusieurs machines.
    Pour enregistrer une seule machine, excluez les arguments "--backup-validator-ids" ou "backup_ids=" de toutes les commandes de cette page.

Maintenant, sur toutes les machines de secours sur lesquelles vous prévoyez d'exécuter votre **validateur principal**, exécutez la commande suivante :
```
doublezero-solana passport find-validator -u mainnet-beta
```

Notez la sortie à la fin de cette commande. C'est la structure pour l'étape suivante.


## 4. Générer la signature {#4-generate-signature}

À la fin de l'étape précédente, nous avons reçu une sortie pré-formatée pour `solana sign-offchain-message`

À partir de la sortie ci-dessus, nous allons exécuter cette commande sur la machine du **validateur principal**.

```
  solana sign-offchain-message \
     service_key=YourDoubleZeroAddress11111111111111111111111111111,backup_ids=ValidatorIdentity222222222222222222222222222,ValidatorIdentity33333333333333333333333333,ValidatorIdentity444444444444444444444444444 \
     -k <identity-keypair-file.json>
```

```

```


## 5. Initier une demande de connexion dans DoubleZero {#5-initiate-a-connection-request-in-doublezero}

Utilisez la commande `request-validator-access` pour créer un compte sur Solana pour la demande de connexion. L'agent DoubleZero Sentinel détecte le nouveau compte, valide son identité et sa signature, et crée le pass d'accès dans DoubleZero afin que le serveur puisse établir une connexion.


Utilisez le node ID, le DoubleZeroID et la signature.

!!! note inline end
      Dans cet exemple, nous utilisons `-k /home/user/.config/solana/id.json` pour trouver l'identité du validateur. Utilisez l'emplacement approprié pour votre déploiement local.

```
doublezero-solana passport request-validator-access -k <path to keypair> -u mainnet-beta \
--primary-validator-id ValidatorIdentity111111111111111111111111111 \
--backup-validator-ids ValidatorIdentity222222222222222222222222222,ValidatorIdentity33333333333333333333333333,ValidatorIdentity444444444444444444444444444 \
--signature Signature111111rrNykTByK2DgJET3U6MdjSa7xgFivS9AHyhdSG6AbYTeczUNJSjYPwBGqpmNGkoWk9NvS3W7 --doublezero-address YourDoubleZeroAddress11111111111111111111111111111
```

**Sortie :**

Cette sortie peut être utilisée pour voir la transaction sur un explorateur Solana. Assurez-vous de configurer l'explorateur sur mainnet-beta ou testnet pour correspondre à votre cluster. Cette vérification est optionnelle.

```bash
Request Solana validator access: Transaction22222222VaB8FMqM2wEBXyV5THpKRXWrPtDQxmTjHJHiAWteVYTsc7Gjz4hdXxvYoZXGeHkrEayp
```

En cas de succès, DoubleZero enregistrera le validateur principal avec ses machines de secours. Vous pouvez désormais basculer entre les IP enregistrées dans le pass d'accès. DoubleZero maintiendra automatiquement la connectivité lors du basculement vers les nœuds de secours enregistrés de cette manière.

```
doublezero connect ibrl
```
